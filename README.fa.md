# BaToHub

BaToHub یک سیستم مدیریت مرکزی سرور است که با Bash نوشته شده است. این پروژه یک نقطه ورودی واحد برای مدیریت ابزارهای سروری مانند SSL، قالب‌های اشتراک، بروزرسانی و یکپارچه‌سازی‌های پنل را از طریق یک معماری ماژولار فراهم می‌کند.

دستور اصلی `BaToHub` است. این دستور پیکربندی مرکزی را بارگذاری می‌کند، بررسی‌های تمامیت و مجوز را انجام می‌دهد و منوی سلسله‌مراتبی برای ماژول‌های نصب‌شده را باز می‌کند.

## توصیف پروژه

BaToHub طوری طراحی شده که یک بار بر روی سرور نصب شود و در طول زمان توسعه یابد. هسته اصلی، مدیریت پیکربندی، گزارش‌گیری، xác minh بروزرسانی، تحقق مجوز، عملیات تعمیر و حذف نصب را مدیریت می‌کند. ماژول‌ها پشتیبانی از پنل‌ها و ابزارهای خاص را بدون تغییر در هسته اضافه می‌کنند.

محصول این مخزن برای Ubuntu 22.04 و Ubuntu 24.04 در معماری amd64 و arm64 طراحی شده است. محیط‌های دیگر ممکن است کار کنند، اما هدف اصلی آنها نیستند.

## لیست ویژگی‌ها

هسته اصلی:
- پیکربندی و دایرکتوری حالت مرکزی
- منmanifest تمامیت برای فایل‌های مدیریت‌شده
- گزارش‌گیری در `/var/log/batohub`
- پیوند تأیید مجوز
- سیستم بروزرسانی با تأیید منmanifest و برگشت به نسخه قبل
- اطلاعات سرور و وضعیت
- نمایش پیکربندی
- نمایش لاگ‌ها
- عملیات تعمیر
- حذف نصب با تأیید

ماژول‌ها:
- کشف خودکار ماژول از طریق `modules/<name>/module.json`
- هر ماژول عملیات نصب، حذف، وضعیت، بروزرسانی و منو را exporse می‌کند
- ماژول‌های غیرفعال به صورت نمونه‌های برچسب‌گذاری‌شده وجود دارند، نه کد شکسته

یکپارچه‌سازی فعال:
- Rebecca
  - نصب، تمدید، وضعیت و حذف SSL
  - نصب، وضعیت و حذف قالب اشتراک BaTo-Ui
  - وضعیت Rebecca و حذف تغییرات BaToHub

در این نسخه فعال نیست:
- PasarGuard
- Sanaei / 3X-UI

## معماری

```
/opt/BaToHub/
  bin/
    batohub
    uninstall
  core/
    main.sh
    license.sh
    update.sh
    module_loader.sh
  lib/
    common.sh
  security/
    integrity.sh
  modules/
    <module>/
      module.json
      module.sh
      ...زیرمجموعه‌ها...
  templates/
    <module>/
      ...
  VERSION
  manifest.json
```

مسیرهای سیستم:
```
/etc/batohub/
  batohub.conf
  integrity.sha256
  license.json
  .license_key
/var/lib/batohub/
/var/log/batohub/
/usr/local/bin/BaToHub -> /opt/BaToHub/bin/batohub
```

جریان کاری:
1. اجرای `BaToHub` منجر به اجرای `bin/batohub` می‌شود.
2. `bin/batohub` `core/main.sh` را اجرا می‌کند.
3. `main.sh` `lib/common.sh` و فایل پیکربندی موضوع‌گذاری‌شده را بارگذاری می‌کند.
4. `main.sh` قبل از باز کردن منو، تحقق مجوز را فراخوانی می‌کند.
5. کشف ماژول، هر `modules/*/module.json` را بارگذاری می‌کند.
6. ماژول‌های فعال بارگذاری می‌شوند و از طریق منو در دسترس قرار می‌گیرند.

## نصب سریع

این دستور را به عنوان root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/isAsli/BaTo-Hub/main/install.sh)
```

این دستور موارد زیر را انجام می‌دهد:
- بررسی دسترسی root
- نصب بسته‌های سیستم ضروری
- ایجاد ساختار دایرکتوری BaToHub در `/opt/BaToHub`
- کپی درخت منبع
- نوشتن پیکربندی مرکزی
- تنظیم دسترسی‌های محدود
- ایجاد دستور `BaToHub`
- نوشتن منmanifest تمامیت

بعد از نصب، این دستور را اجرا کنید:

```bash
BaToHub
```

## نصب دستی

1. درخت منبع را در محل موقتی روی سرور مقصد دانلود کنید.
2. `install.sh` را به عنوان root از آن دایرکتوری اجرا کنید.
3. تأیید کنید که `/usr/local/bin/BaToHub` به `/opt/BaToHub/bin/batohub` اشاره می‌کند.
4. `BaToHub` را اجرا کنید و در صورت نیاز مرحله مجوز را تکمیل کنید.
5. برای یکپارچه‌سازی Rebecca، در صورت وجود Rebecca روی سرور، قالب BaTo-Ui را از منوی ابزارها نصب کنید.

مثال مراحل:

```bash
apt-get update
apt-get install -y curl ca-certificates openssl unzip rsync python3 whiptail dnsutils iproute2 procps coreutils certbot
bash ./install.sh
BaToHub
```

## تأیید پس از نصب

م 직후 به موارد زیر دقت کنید:
- `BaToHub` بدون خطا شروع می‌شود
- نسخه گزارش‌دهی‌شده توسط BaToHub با `/opt/BaToHub/VERSION` همخوانی دارد
- `/etc/batohub/batohub.conf` برای همه قابل خواندن نیست
- `/etc/batohub/integrity.sha256` وجود دارد و `sha256sum -c` را 통과 می‌کند
- `/var/log/batohub/batohub.log` وجود دارد
- ماژول‌های غیرفعال به عنوان غیرقابل استفاده نمایش داده می‌شوند و به عنوان کد فعال اجرا نمی‌شوند

## شروع سریع

1. `BaToHub` را اجرا کنید.
2. در صورت تقاضا، تحقق مجوز را تکمیل کنید.
3. از منوی اصلی برای بررسی وضعیت بروزرسانی، اطلاعات سرور و ابزارها استفاده کنید.
4. اگر Rebecca نصب شده است، از منوی ابزارها وارد Rebecca شوید و BaTo-Ui را نصب کنید یا SSL را مدیریت کنید.

## مرجع دستورها

| دستور | کاربرد |
| --- | --- |
| `BaToHub` | باز کردن منوی مرکزی |
| `install.sh` | نصب BaToHub به عنوان root |
| `bin/uninstall` | حذف فایل‌های مدیریت‌شده BaToHub با تأیید |
| `sha256sum -c /etc/batohub/integrity.sha256` | بررسی تمامیت فایل‌های مدیریت‌شده |

اقدامات منوی شکستی هستند. عملیات تخریب‌کاران نیاز به عبارت تأیید صریح دارند.

## سیستم ماژول

هر ماژول دایرکتوری‌ای تحت `modules/<name>` با حداقل موارد زیر است:
- `module.json`
- `module.sh`

`module.json` ماژول را توصیف می‌کند:

```json
{
  "name": "example",
  "version": "0.0.1",
  "description": "Example module",
  "status": "active",
  "path": "modules/example",
  "entry": "modules/example/module.sh",
  "dependencies": []
}
```

`module.sh` توابع رابط接口ی را که توسط هسته استفاده می‌شوند، تعریف می‌کند:
- `<name>_menu`
- `<name>_install`
- `<name>_uninstall`
- `<name>_status`
- `<name>_update`

برای افزودن ماژول جدید:

1. `modules/<name>/module.json` را ایجاد کنید.
2. `modules/<name>/module.sh` را ایجاد کنید.
3. پنج تابع رابط接口ی را پیاده‌سازی کنید.
4. اگر ماژول فعال است، `"status": "active"` را در `module.json` آن تنظیم کنید.
5. `install.sh` را اجرا کنید یا در صورت نیاز نصب را به‌روز کنید.

کشف ماژول خودکار است. هسته نیازی به ویرایش برای هر ماژول جدید ندارد، مشروط بر رعایت قرارداد نام‌گذاری.

## مرجع پیکربندی

`/etc/batohub/batohub.conf` توسط کتابخانه موضوع‌گذاری می‌شود. کلیدهای مرتبط:

| کلید | توضیح | پیش‌فرض |
| --- | --- | --- |
| `APP_NAME` | نام برنامه | `BaToHub` |
| `APP_VERSION` | نسخه برنامه | `0.0.1` |
| `LICENSE_API` | endpoint تأیید مجوز | به‌صورت مرکزی پیکربندی‌شده |
| `LICENSE_PRODUCT` | شناسه محصول ارسال‌شده هنگام تأیید | `batohub` |
| `SUPPORT` | تماس پشتیبانی نمایش‌دهی‌شده در شکست مجوز | `@BaTo_Help` |
| `CHANNEL` | تماس کانال | `@BaToHub` |
| `GITHUB_REPO` | مخزن GitHub مورد استفاده برای بررسی‌های انتشار | `isAsli/BaTo-Hub` |
| `UPDATE_MANIFEST` | URL منmanifest از راه دور برای بروزرسانی‌ها | به‌صورت مرکزی پیکربندی‌شده |
| `MANIFEST_SIGNATURE` | URL امضا منmanifest از راه دور | به‌صورت مرکزی پیکربندی‌شده |
| `INSTALL_DIR` | دایرکتوری اصلی برنامه | `/opt/batohub` |
| `STATE_DIR` | دایرکتوری حالت پایدار | `/var/lib/batohub` |
| `CONFIG_DIR` | دایرکتوری پیکربندی | `/etc/batohub` |
| `LOG_DIR` | دایرکتوری لاگ | `/var/log/batohub` |
| `REBECCA_DIR` | دایرکتوری نصب Rebecca که توسط BaToHub انتظار می‌رود | `/opt/rebecca` |
| `TEMPLATE_ROOT` | ریشه قالب نوشته‌شده در env Rebecca | `/opt/rebecca/bato-templates` |
| `GLOBAL_CMD_NAME` | مسیر دستور جهانی ایجادشده توسط نصب‌کننده | `/usr/local/bin/BaToHub` |

## مکانیسم بروزرسانی

بروزرسانی‌ها بر اساس یک منmanifest از راه دور بررسی می‌شوند. جریان مورد انتظار عبارت است از:
1. دانلود منmanifest از طریق HTTPS.
2. تأیید امضا منmanifest با GPG.
3. خواندن نسخه، URL بسته و SHA-256 از منmanifest.
4. دانلود بسته.
5. تأیید SHA-256 بسته.
6. پشتیبان‌گیری از نصب فعلی.
7. استخراج بسته جدید.
8. جایگزینی فایل‌های مدیریت‌شده.
9. بازسازی منmanifest تمامیت.
10. تأیید نتیجه.
11. برگشت به نسخه قبل در صورت شکست تأیید.

امضای منmanifest برای اعتماد به بروزرسانی ضروری است. اگر تأیید امضا شکست بخورد، بروزرسانی نادیده گرفته می‌شود.

اطلاعات انتشار GitHub ممکن است برای ارجاع بررسی شود، اما جریان منmanifest امضا شده را جایگزین نمی‌کند.

## مدل امنیتی

BaToHub از راهکارهای دفاعی متعددی استفاده می‌کند:
- پیکربندی مرکزی با دسترسی‌های محدود
- منmanifest تمامیت برای فایل‌های مدیریت‌شده
- نوشتارهای قفل‌شده برای حالت مشترک در جای‌های عملی
- فایل‌های موقت که با `mktemp` ایجاد می‌شوند
- Expansion‌های متغیر به‌درستی عطف‌القاعده
- اعتبارسنجی ورودی‌ها برای دستورالعمل‌ها و نام‌های ماژول
- دسترسی‌های محدود بر روی کلیدهای خصوصی و پیکربندی حساس
- گزارش‌گیری به‌صورت متن ساده بدون escapes ترمینال

محدودیت‌ها:
- دسترسی root امکان تغییر یا حذف فایل‌های محلی را دارد. بررسی‌های تمامیت تغییرات را کشف می‌کنند؛ اما سیستم را فیزیکی غیرقابل تغییر نمی‌کنند.
- اعتماد به بروزرسانی از راه دور به کلید امضا و منبع امضا بستگی دارد.
- تأیید مجوز به دسترسی شبکه به API پیکربندی‌شده بستگی دارد.
- مدیریت SSL به Certbot و دسترسی به پورت 80 یا چالش جایگزین بستگی دارد.
- نصب‌کنندگان FromGlibPtr‌ wax، مانند نصب‌کننده باینری Rebecca، پس از دانلود اجرا می‌شوند و به اعتماد منبع خود وابسته‌اند.

فرض نکنید که سیستم غیرقابل تغییر است. این سیستم برای کشف دستکاری و دشوارتر کردن تغییرات نا아미내셔널 طراحی شده است.

## گزارش‌گیری و عیب‌یابی

لاگ‌ها در مسیر زیر نوشته می‌شوند:
```
/var/log/batohub/batohub.log
```

هر ورودی شامل timestamp و عملیات یا خطا است.

بررسی‌های رایج:
- وجود مسیر نصب را تأیید کنید
- دسترسی‌های `/etc/batohub` و `/var/log/batohub` را تأیید کنید
- منmanifest تمامیت را بررسی کنید
- فایل لاگ را برای خطاهای اخیر بررسی کنید
- بررسی کنید که دستورات لازم نصب شده‌اند
- قبل از عملیات SSL، بررسی کنید که پورت 80 دسترس‌پذیر است
- قبل از تغییرات قالب یا SSL، وجود فایل `.env` Rebecca را تأیید کنید

اگر بروزرسانی شکست بخورد:
- نصب‌کننده دایرکتوری پشتیبان با timestamp نگه می‌دارد
-محل دقیق شکست را از لاگ بررسی کنید
- پس از اطمینان از اعتمادپذیری منبع بسته، فقط سپس بروزرسانی را مجدّد اجرا کنید

## حذف نصب

دستور حذف نصب را از منوی BaToHub یا مستقیماً اجرا کنید:

```bash
/opt/BaToHub/bin/uninstall
```

نصب‌کننده حذف:
- فایل‌ها و دایرکتوری‌هایی که حذف می‌شوند را نشان می‌دهد
- تقاضای تأیید دارد
- به‌صورت اختیاری حذف怎么样 قوبلی نصب CertbotBaToHub را دارد
- فایل‌های مالکیتBaToHub را حذف می‌کند
- Rebecca را به‌خود حذف نمی‌کند
